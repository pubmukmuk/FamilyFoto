# 📁 PROJECT DOCUMENTATION LAYOUT
This document outlines best practices for organizing all project-related documentation, including user guides, developer notes, UML diagrams, changelogs, and auto-generated files like JavaDoc and PyDoc outputs.

## 📁 Folder: `docs/`

All documentation should live inside the top-level `docs/` folder. This ensures:
- A single source of truth for documentation
- Consistent structure across projects
- GitHub Pages support (if published)

## 📂 Recommended Structure

<pre>
docs/
├── 📘 PROJECT-DOCS.md ← This file (documentation guidelines)
├── 📄 README.md ← Project overview or main landing page
├── 📜 CHANGELOG.md ← Manual changelog (or Git-based auto-export)
├── 📁 images/ ← Screenshots, diagrams, logos
├── 📁 diagrams/ ← UML, PlantUML, system architecture
│ ├── ssh-auth-flow.puml
│ └── tile-placement-flow.puml
├── 📁 usage/ ← CLI examples, shell scripts, workflows
│ ├── WORKFLOW.md
│ ├── FILENAMING-OPTIONS.md
│ └── ORGANIZED-OPTIONS.md
├── 📁 devnotes/ ← Internal notes, decisions, journal logs
│ └── 2025-08-24_refactor-notes.md
├── 📁 javadoc/ ← Auto-generated JavaDocs (do not edit manually)
│ └── index.html
├── 📁 pydoc/ ← Auto-generated Python docs (optional)
│ └── index.html
└── 📁 drafts/ ← Ideas, unapproved content, experimental designs
</pre>


---

## 🧩 Document Types and Purpose

| File/Folder        | Purpose                                                        |
|--------------------|----------------------------------------------------------------|
| `README.md`        | Entry point for GitHub or documentation viewers               |
| `CHANGELOG.md`     | Summarize manual or version-controlled changes                |
| `images/`          | Store logos, icons, UI screenshots, or rendered diagrams       |
| `diagrams/`        | PlantUML, flowcharts, data models, architecture                |
| `usage/`           | User-facing guides, config examples, CLI walkthroughs          |
| `devnotes/`        | Developer logs, design decisions, architecture notes           |
| `javadoc/`         | Auto-generated by Maven (exclude from Git or `.gitignore` it) |
| `pydoc/`           | Optional: use Sphinx or `pdoc` to generate from Python code    |
| `drafts/`          | Temporary notes, not yet approved for main docs                |

---

## 📐 Diagram Best Practices

- Use `.puml` (PlantUML) format for diagrams, commit source files and optionally rendered PNGs.
- Prefix filenames clearly:  
  - `auth-flow.puml`, `tile-placement.puml`, `entity-hierarchy.puml`
- Store rendered images in `images/diagrams/` if needed.

Example:

<pre>
diagrams/
├── ssh-auth-flow.puml
images/diagrams/
├── ssh-auth-flow.png
</pre>


---

## 🧪 Versioning and Backups

- Commit all `.md`, `.puml`, and config files to Git.
- Exclude generated HTML (`javadoc/`, `pydoc/`) with `.gitignore`.
- Use version tags and `VERSIONS.csv` or `VERSIONS.md` to track release documents.

---

## ✅ Tips

- Use Markdown tables for consistency in usage guides.
- Use `##==================` blocks to separate major sections.
- Keep diagrams and references in sync with code version (add version header if needed).
- Document assumptions and edge cases during design and testing.

---

## 📦 Optional: Publish with GitHub Pages

If you'd like to make your documentation public:

1. Enable GitHub Pages → select branch: `main`, folder: `/docs`
2. Use `README.md` as your landing page
3. Link other markdown files as needed
